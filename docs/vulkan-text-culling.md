# Martensite retained text face culling

Text extraction now retains `Graphic3d_AspectText3d::FaceCulling()` on every glyph
pass. Explicit back/front rejection works for oriented text, billboards, own
anchors and mirrored structures. The existing view override and Vulkan dynamic
front-face state remain authoritative after extraction.

For `Auto`, native OCCT 3d097a0 permits back culling only for an eligible closed
group. Hatch, Blend, Mask and MaskBlend disable automatic culling; BlendAuto does
so when the front material is transparent. Font coverage blending does not
replace this aspect policy. The lowerer's existing clipping eligibility remains
part of the closed-group input.

Run the CPU tests without OCCT or a GPU:

```sh
cargo test -p martensite-vulkan --all-targets
```

`text_culling_tests` replays 384 committed rows generated by actual
`OpenGl_Workspace::ApplyAspects(false)` and queried GL state. Retained-scene tests
also exercise live aspect changes and view overrides with `RecordingDevice` and
`FixedGlyphSource`.

Native generation is local-only and uses the pinned sibling OCCT build:

```sh
g++ -std=c++17 -I ../RustyCADKernel/target/occt-all-full/include/opencascade \
  tools/oracle/martensite_vulkan_text_culling_policy.cxx \
  -L ../RustyCADKernel/target/occt-all-full/lin64/gcc/libi \
  -Wl,-rpath,"$PWD/../RustyCADKernel/target/occt-all-full/lin64/gcc/libi" \
  -lTKOpenGl -lTKV3d -lTKService -lTKMath -lTKernel -o /tmp/text-culling-policy
DISPLAY=:1 /tmp/text-culling-policy > /tmp/text-culling-policy.txt
cmp /tmp/text-culling-policy.txt crates/vulkan/tests/fixtures/text_culling/native-policy.txt
```

The capture generator uses the same compiler flags with
`martensite_vulkan_text_culling_capture.cxx`. Its arguments are `mode prefix`;
output is top-down 128×128 RGBA8 and little-endian float depth. Martensite uses:

```sh
cargo run -p martensite-vulkan --example text_culling_capture -- front-back /tmp/text-front
cargo run -p martensite-vulkan --release --example text_culling_performance
```

Set `VK_DRIVER_FILES` and `MARTENSITE_VULKAN_DEVICE=0` to choose lavapipe or the
native host profile. Capture runs enable validation. The performance probe uses
optimized code without validation and records 100 complete redraw/readback
samples after 20 warmups for each of the 19 cases. It establishes distributions,
not an improvement against a baseline.

[Local evidence](../porting/runtime-evidence/text-culling-2026-10-11/) retains
source/device identity, policy provenance, capture PNGs, precise pixel/depth
comparison statistics and lifecycle diagnostics. Host captures match native
RGBA bytes. Lavapipe has up to 18 differing channel bytes, each differing by one;
coverage is identical on both devices. Maximum depth error is 1.2e-7.

The empty displayed-group lifecycle is deliberately retained: display a triangle,
clear the group, transform the empty displayed structure, then add text without
redisplaying. Both native OCCT and Martensite omit that draw. A fresh structure
transformed before adding text and displayed afterward instead renders 102
foreground pixels. This diagnostic does not justify a bounds behavior change.

This slice does not claim complete `OpenGl_Text` parity. The coordinator integrated
and checked Shadow together with culling, and subsequently checked Subtitle
culling on both devices. The [combined main receipt](../porting/runtime-evidence/visualization-integration-2026-10-12/integrated-main-71131d660/)
records its exact source revision; [Subtitle integration](../porting/runtime-evidence/subtitle-text-2026-10-12/integration.json)
records the later checks. Windows and macOS remain untested.
